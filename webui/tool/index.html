Run it locally — it's free & private

You're viewing the hosted interface. For privacy, I never see what you analyze — the code stays on your machine. Start the local engine, and this page connects to it automatically. Pick the easiest option:

One file, one command. On first run it fetches the engine from the official GitHub repo, installs what it needs, and starts — no clone required. It starts the same engine as server.py, so run one of the two, never both.

  1. Download the launcher above (or copy it straight from GitHub).
  2. Run it: python3 scriptsentry.py --port 8000 — the first run downloads the engine.
  3. Open the dashboard it prints — http://127.0.0.1:8000.
  4. Paste the pairing token when the dashboard asks for it — the token is printed in the same terminal, right under the dashboard address.
# downloads & starts the engine on first run
python3 scriptsentry.py --port 8000
  1. Get the project: clone or download ScriptSentry.
  2. Open a terminal inside the project folder.
  3. Install deps: pip install -r requirements.txt
  4. Start the server: python3 server.py --port 8000 (the full-repo way to start the same engine the launcher downloads).
  5. Open http://127.0.0.1:8000 and paste the pairing token printed in the server's terminal when the dashboard asks for it.
git clone https://github.com/AmitPal-CyberBuddy/ScriptSentry.git
cd ScriptSentry
pip install -r requirements.txt
python3 server.py --port 8000
  1. Install the package: clone the repo, then pip install . (or pipx install .).
  2. Start the dashboard: scriptsentry-server --port 8000 — same pairing-token flow as the other paths.
  3. Prefer the CLI? scriptsentry --help runs scans and every report format without a browser.
  4. Docker ships the Playwright Chromium for runtime evidence: docker run --rm -p 8000:8000 scriptsentry.

Data & storage

What this machine keeps: the scan history below in history.db (SQLite, WAL — up to ~200 scans, report payloads capped at 16 MB each) and anonymous ETA timing stats in eta_calibration.json. URL downloads/uploads live in a temporary workspace that is deleted after the scan.

Never stored: cookie values, request bodies, localStorage values, form inputs. Scan content never leaves your machine — optional CLI AI notes come from your own local model and live only in the reports that run writes.
